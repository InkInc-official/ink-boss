## 総評

コンセプトは**非常に優秀**です。  
「レシピレス」「非Electron」「LLM統合」「Googleログイン対応」という組み合わせは、Ferdium/Ramboxの明確な次世代として差別化でき、需要が高いと思います。特に**URL登録だけで完結**する体験は強力な売りになります。

ただし、現状の最大ボトルネックは**Tauri v2のWebView問題**と**Googleログイン突破**の2点です。この2つを解決しない限り、プロジェクトの本質的な価値が発揮できません。

---

## 1. 主要課題への評価

### 1-1. WebView真っ黒問題（最重要）
- **原因**: 正確に理解できています。Tauri v2で`<webview>`タグが廃止された影響です。
- **WebviewWindow方式**: 公式推奨ですが、**実装コストが高く、リスクも大きい**（特にLinux + webkit2gtkでの安定性）。
- **結論**: Tauri v2に固執する価値は薄れてきています。

### 1-2. Googleログイン問題
これが**Ink Hubの成否を分ける最大のポイント**です。  
システムWebView系（Tauri/Wails）はUser-Agent偽装だけでは限界があり、Googleの検知を長期的に回避し続けるのは困難です。

---

## 2. フレームワーク選定の推奨

### 最推奨: **PySide6 + QtWebEngine** ★★★★★

**理由**:
- QtWebEngineは**Chromiumベース**のため、Googleログインの通過率が圧倒的に高い
- `QWebEngineProfile`により**各サービスごとの完全セッション分離**が非常に綺麗に実現可能
- PythonはInk Inc.の既存資産（Ink Memory等）と親和性が高い
- Ubuntu 24.04との相性も良好
- LGPLライセンスでOSSとして問題なし

**懸念点への回答**:
- **重さ**: Electronより明らかに軽量。実用上十分軽快
- **UI移植**: Sidebar + 中央WebViewというシンプル構成のため、思ったより工数はかからないはず（QWebEngineView + PySide6のWidget構成で再現可能）

## 3. あなたの質問への直接回答

### Q1. Tauri v2でWebViewを正しく動かす方法はあるか？
→ **現実的にはありません**（WebviewWindow以外）。  
WebviewWindowを試すなら**1週間以内にPoC**を作って判断してください。ダメなら潔く撤退を推奨。

### Q2. Ubuntu 24.04でGoogleログインを突破できる最適解は？
→ **PySide6 + QtWebEngine**が現時点で最も現実的かつ強力。

### Q3. PySide6 vs Tauri WebviewWindowの比較
- **実装難易度**: PySide6の方がセッション管理・ログイン突破は簡単。UI部分はTauriの方が楽。
- **パフォーマンス**: Tauriが勝るが、差は「体感できるレベル」ではない（特に複数サービス同時使用時）。
- **メンテナンス性**: Pythonの方が長期的に有利（特にあなたの場合）。

### Q4. 他に見落としている選択肢
- **Tauri v2 + custom webviewプラグイン**（将来的）
- **Qt for Python + QML**（よりモダンなUIにしたい場合）
- **Avalonia + WebView2**（Windows最優先なら検討価値あり。ただしLinuxは別途対応必要）

### Q5. セッション分離 + Googleログインの最もシンプルな方法
**PySide6の場合**:
1. 各サービスごとに別々の`QWebEngineProfile`を作成（`storageName`や`cachePath`をサービスIDごとに分離）
2. User-Agentを最新のChrome相当に設定
3. `QWebEnginePage`をプロファイルに紐づける
4. Cookie/Storage/LocalStorageもプロファイル単位で自動分離

これでほぼ「別々のChromeインスタンス」を作った状態になります。
