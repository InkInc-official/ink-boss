# セカンドオピニオン：Ink HubのWebView運用に関する評価と提案

## 概要
本セカンドオピニオンは、2026年5月時点の技術動向を踏まえ、Ink HubのWebView運用において最適な選択肢を評価・提案したものです。主な焦点はGoogleログインの確実性、セッション分離の容易さ、長期的な安定性にあります。

## 主要評価ポイント

### 1. Tauri v2のWebView廃止とその影響
- `<webview>`タグは廃止され、WebviewWindowへの移行が公式推奨。
- Ubuntu 24.04ではWebKitGTK 4.1への対応が必要。
- WebviewWindowは座標同期やZ-order制御など実装の難易度が高く、Wayland対応も課題。

### 2. Googleログイン突破の最適解
- **PySide6 + QtWebEngine**は、WebViewのセッション分離とGoogleログインの確実性において最良の選択肢。
- Tauri WebviewWindowとUA偽装は短期的に通る可能性はあるが、長期的にはブロックリスクが高い。
- OAuth PKCEを用いた外部ブラウザ連携も有効だが、WebView内のUI統合には制約。

### 3. PySide6 + QtWebEngineとTauri WebviewWindowの比較
- **実装の容易さ**：PySide6は1行でセッション分離可能。Tauriは設定が複雑。
- **パフォーマンス**：PySide6はメモリ使用量や起動速度で優位。
- **Googleログインの確実性**：PySide6はChromeと同じUser-Agent・TLSフィンガープリントで確実に突破可能。TauriはWebKitGTKの制約でリスク。
- **既存資産の流用性**：React/TS資産はそのまま使えるのはTauriだが、UI書き直しが必要。

### 4. 推奨アプローチ
- **最優先事項：** Googleログインの確実性とセッション分離の容易さ。
- **結論：** PySide6 + QtWebEngineへの移行を強く推奨。
- **理由：** 長期的な安定性と資産の流用、信頼性に優れるため。

## まとめ
- **PySide6 + QtWebEngine**は、「必須要件」を満たし、「理想」の軽量性も維持可能。
- **Tauri**はUI資産の流用や軽量性に優れるが、長期的なGoogleログインの確実性にはリスク。
- ink Hubの成功には、Googleログインの突破とセッション分離の信頼性が不可欠。これらを最優先に考えるなら、PySide6への移行が最適解と考えられる。
